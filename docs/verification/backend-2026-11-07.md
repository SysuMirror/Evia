## Limits of this evidence

- The fixture publishes a custom `smoke_page_view` event. Its selected-event
  count demonstrates PV semantics, and its unique metric uses raw UID values.
  The `sys.*` registry remains fixture-only; automatic browser instrumentation
  and a resolved identity graph are not established by this result.
- Query results remain bounded snapshots with provisional coverage. Their
  watermark records observed data, without establishing global pipeline
  completeness, settled statistics or cursor pagination.
- The topology has a single Kafka broker/controller, ClickHouse node and Redis
  process with disposable datasets. It does not verify replication-factor-three
  failover, production recovery, physical-media durability or capacity.
- The managed rootless Docker daemon reported no per-container cgroup CPU/RAM
  enforcement. Compose records requested limits; application memory settings
  and bounded tmpfs directories were configured and checked. This environment
  does not prove per-container limit enforcement.
- Browser SDK/public integration skills, identity resolution/Flink processing,
  member administration, data lifecycle, reports/dashboards/exports and the
  native console migration remain separate delivery work. Full R1 and production
  readiness are not claimed.
