# 高基数长尾身份分布验证记录（2026-11-13）

## 范围

补齐容量工程的「长尾身份/字段分布」缺口。此前两类证据都用浅分布：
514/728 矩阵与混合读写演练里 UID 接近均匀取模，没有「少数热点身份吸收
大部分事件、大量稀疏身份只出现一两次」的真实倾斜。本切片构造确定性的
高基数长尾身份分布，经真实 Kafka→ingest-worker→ClickHouse 落库后，
验证存储层对热点查询、深尾查询与去重基数统计都给出**分布精确**且有界
的结果。

本切片不改动任何生产 Go 代码；新增物为一个集成测试、一个演练脚本与纯
逻辑单测、文档。

## 交付内容

- `backend/internal/pipeline/long_tail_integration_test.go`：
  `TestHighCardinalityLongTail`（integration 标签，
  `EVIA_TEST_LONGTAIL_DRILL=1` 门控）。
- `tooling/ha/long_tail_drill.py` 与 22 项纯逻辑单测（纳入
  `make ha-tools-test`）：确定性分配规则、期望计数、集中度指标与报告
  评估。

## 确定性长尾分布规则

Go 装载器与 Python 评估器实现同一规则，不共享 fixture 文件：

- 4000 个事件、800 个身份、20 个热点身份、热点份额 0.8；
- 前 `round(4000*0.8)=3200` 个事件在 20 个热点身份间均匀轮转（每个热点
  160 个事件）；
- 其余 800 个事件在 780 个稀疏身份间均匀轮转（最稀疏身份仅 1 个事件）；
- 800 个稀疏事件 ≥ 780 个稀疏身份，保证全部 800 个身份都被覆盖，可对
  `uniqExact` 做精确断言。

该规则无随机、零基序号、跨语言可复现。纯函数单测同时证明了小样本下深尾
不被覆盖的真实特性（1000 事件/800 身份时仅覆盖 220 个身份）。

## 先红后绿（测试自身缺陷修正）

- Go 不能把编译期浮点表达式 `int(0.5 + 4000*0.8)` 转 int，改为显式
  常量 `ltHotEvents = 3200` 并在注释钉住分布契约。
- 发布循环最初用一基序号（1..4000）而分配规则是零基（0..3999），导致
  热点 uid 0 少一个事件（实测 159 vs 期望 160），改为零基后精确一致。

## 验证的不变量

1. **精确逐身份计数**：抽样热点（index 0/1/19）与稀疏（index 20/100/799）
   身份，ClickHouse 计数严格等于分布规则的期望值。
2. **去重基数精确**：`uniqExact(uid)` 严格等于 800，证明去重视图没有
   合并或丢失身份。
3. **热点集中度**：观测热点份额 0.8，与配置一致；最热身份 160 事件 vs
   最稀疏身份 1 事件，头尾比 160。
4. **有界读延迟**：热点 UID 过滤、深尾 UID 过滤、去重基数三类查询各
   重复 12 次，p95 全部在 10 秒执行预算内，并从 `system.query_log`
   报告峰值内存。

  ClickHouse 26.8.36.3（`127.0.0.1:18123`），当前运行中的 dev 容器。

## 真实演练结果

命令（工具链激活，凭据经环境变量传入）：

```
python3 tooling/ha/long_tail_drill.py
```

两轮独立运行均 `status=passed`：

| 指标 | 第一轮 | 第二轮 |
| --- | --- | --- |
| 事件总数 | 4000 | 4000 |
| 身份基数 | 800（全覆盖） | 800（全覆盖） |
| 观测热点份额 | 0.8 | 0.8 |
| 最热/最稀疏身份事件数 | 160 / 1 | 160 / 1 |
| 逐身份计数核对 | 6 个抽样全部精确 | 同左 |
| `uniqExact(uid)` | 800 | 800 |
| 热点 UID 查询 p95 | 32ms | 32ms |
| 深尾 UID 查询 p95 | 33ms | 33ms |
| 去重基数查询 p95 | 33ms | 32ms |
| 峰值查询内存 | 约 18.4 MiB | 同量级 |
| 残留主题/数据库 | 无 | 无 |

## 边界与诚实声明

- 单 broker、单 ClickHouse 节点、4000 事件规模：延迟是单机小数据集基线，
  不能外推多节点水平扩展或千万用户量级。
- 分布是确定性的合成倾斜（两段均匀轮转），复现了头尾数量级差异但不等同
  真实生产的 Zipf 曲线；真实分布需从生产事件采样获得后再压测。
- 存储层直连 ClickHouse，绕过公开 API 的鉴权、排队与异步作业轮询；端到端
  延迟仍以 514/728 矩阵为准。
- 本证据不改变 514/728 的失败记录；长保留期、多租户隔离与跨故障域拓扑下的
  长尾容量仍需独立专项。
