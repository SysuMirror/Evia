# 机器访问与凭据

机器主体用于业务方的 Agent、发布作业和服务端工具。它拥有独立的主体 ID，不借用创建人的账号或会话。管理凭据与浏览器公开写 key、服务端采集凭据分开；三者不能互换。

## 权限与资源边界

一个机器主体固定属于一个项目和一个环境，权限集合在创建后不可修改。开发环境写入与生产环境只读应创建两个主体，避免将环境数组和操作数组组合成额外权限。修改用途时创建替代主体并撤销原主体。

| 权限 | 允许的操作 |
| --- | --- |
| `project.read` | 读取所属项目元数据 |
| `catalog.drafts.read`、`catalog.drafts.write` | 读取/校验或创建/编辑**项目共享草稿** |
| `catalog.releases.read` | 读取所属环境发布、激活状态及已发布定义 |
| `catalog.releases.publish` | 根据指定草稿构建所属环境的不可变发布 |
| `catalog.releases.activate` | 比较当前版本后激活已就绪发布 |
| `sources.read`、`sources.write`、`sources.rotate` | 分别读取、创建/更新、轮换所属环境来源 |
| `queries.read`、`queries.run` | 分别发现/校验/读取查询，或提交/取消自己的查询 |
| `queries.raw.read` | 额外允许原始事件、行为链及引用身份字段的查询 |
| `analyses.read`、`analyses.write`、`analyses.publish`、`analyses.run` | 分别读取、编辑、发布、运行保存分析 |
| `metrics.read`、`metrics.write`、`metrics.publish`、`metrics.run` | 分别读取、编辑/校验、发布、运行独立原子指标 |
| `dashboards.read`、`dashboards.write`、`dashboards.publish`、`dashboards.run` | 分别读取、编辑、发布、运行看板 |
| `data.erasure` | 创建按身份数据删除作业（独立敏感授权，人类会话仅 owner） |
| `data.export` | 创建数据导出作业与一次性下载授权（独立敏感授权，人类会话仅 owner） |

事件草稿本来就是项目共享资源，草稿权限不受环境隔离，不能把生产环境主体解释为只能修改生产草稿。发布、激活、来源、查询、指标、保存分析和看板按实际资源的环境检查。机器列出事件时必须显式传入所属环境，同时需要草稿读取和发布读取权限；单个已发布事件版本还须属于该环境的发布记录。

权限不自动包含其他权限。来源更新和轮换使用各自的预检查，不要求额外授予来源读取。指标及保存分析运行仍需要 `queries.run`，看板各子查询也必须分别通过查询与原始数据权限检查；入队前一次性验证全部组件。看板内部使用固定的分析版本不等同于取得整个分析目录的读取权。

`queries.raw.read` 不只判断查询名称，还检查身份条件、过滤、分组、指标及漏斗约束中的身份字段，防止用聚合查询输出 UID 等标识。缺少权限时不会通过换一个查询类型绕过限制。

新增 `metrics.*` 是独立授权，不由原 `analyses.*` 推导。迁移 `012` 只扩充白名单，旧主体的权限不变；使用新用途需签发合适的新主体。指标的统计口径与接口见[版本化指标](metrics.md)。

## 接口

令 `P = /api/v1/projects/{project_id}`。控制台和机器生命周期接口使用同一资源格式、错误结构、请求 ID 与分页规范，权威定义见 [OpenAPI](../contracts/http/openapi.json)。

| 方法与路径 | 认证及语义 |
| --- | --- |
| `GET /api/v1/machine-identity` | 机器 Bearer，返回主体、凭据、项目、环境、权限和到期时间 |
| `GET P/machine-principals` | 当前人类 owner，会话认证，支持 `cursor`、`limit`，返回项目全部环境 |
| `POST P/machine-principals` | 当前人类 owner，会话与 CSRF，必需 `Idempotency-Key` |
| `GET P/machine-principals/{principal_id}` | 当前人类 owner，主体及全部凭据元数据，返回 `ETag` |
| `POST P/machine-principals/{principal_id}/credential-rotations` | 当前人类 owner，会话与 CSRF、带双引号的 `If-Match`、幂等键 |
| `DELETE P/machine-principals/{principal_id}` | 当前人类 owner，会话与 CSRF、`If-Match`，永久撤销主体 |
| `DELETE P/machine-principals/{principal_id}/credentials/{credential_id}` | 当前人类 owner，会话与 CSRF、`If-Match`，撤销指定凭据 |

机器不能创建项目、枚举所有项目、登录控制台或管理机器凭据。项目资源接口必须显式选择支持机器认证；新增接口不会自动得到 Bearer 支持。携带 Bearer 与会话 Cookie 的混合请求、多个 Authorization 头和格式错误的 Bearer 都被拒绝，不会回退到另一种认证。会话写操作继续要求 CSRF，Origin 检查保持有效。

创建请求包含 `name`、`environment`、`permissions` 和 `expires_at`。名称为 1–128 个字符，权限最多 26 个且不重复。凭据有效期按数据库时钟校验，为 1 分钟到 90 天；选择略大于一分钟的有效期可避免传输时间使请求越界。每个项目最多保留 256 个机器主体，每个主体最多保留 128 条历史凭据，撤销不会释放历史条目。达到凭据上限应创建替代主体；历史归档和扩大项目上限需另行交付，不能直接删除审计引用。

轮换输入为新的 `expires_at` 与 `overlap_seconds`，交叠期为 0–300 秒。轮换会缩短旧凭据的剩余期限，不延长任何旧凭据。零交叠适合立即切换，有界交叠便于部署新凭据。轮换与撤销递增主体修订；并发变更返回明确的修订冲突，不能覆盖别人刚完成的操作。

## 一次性密钥与未知结果

凭据使用 `evia_m_` 前缀与 256 位随机秘密，数据库仅保存摘要。首次创建或轮换返回：

```json
{
  "principal": { "...": "主体元数据" },
  "credential": { "...": "凭据元数据" },
  "secret_available": true,
  "secret_once": "仅在首次成功响应中出现"
}
```

此示意不是可提交请求。真实类型由契约定义。相同幂等键和相同规范化输入的重试返回原资源元数据、`secret_available: false`，不再次产生密钥。使用相同键提交不同输入返回冲突。已完成发行的重试不重新套用“距现在一分钟”的发行条件；返回资源的当前撤销/到期元数据。

响应丢失后，应保留原始请求、幂等键和修订重试，先确认发行结果。若秘密已丢失，必须明确发起一次新轮换，不应创建重复主体或假装已找回秘密。`GET`、列表、错误、审计和幂等记录都不返回明文凭据。控制台秘密仅保留在一次性局部状态，不进入查询缓存、URL、持久存储、截图或日志。

## 持久化、审计和撤权

迁移 `010_machine_principals.sql` 新增公共主体登记表，保留既有人类账号 UUID，为机器分配独立 UUID。11 个既有业务归属外键从账号改为主体；会话和项目成员仍只引用人类账号。新增账号触发器维护人类主体登记，历史发布和幂等键不改写。

业务事务锁定当前主体及确切凭据，重新核对状态、到期、项目、实际环境和所需操作。HTTP 身份信息只用于归属和发现，不能作为最终授权缓存。事务内审计记录机器凭据 ID，并以组合外键确保凭据属于审计主体；没有存储明文秘密。

查询任务保存发行时的凭据 ID。领取、约 250 毫秒的工作租约检查及完成写入使用原凭据重新授权，轮换后的新凭据不能替旧凭据恢复尚未完成的工作。取消仍遵循机器只能取消自身任务、人类 owner/editor 保留项目管理权限的规则。

撤销与业务事务按锁顺序串行化：已取得授权锁的事务可以先完成，撤销提交后新的授权检查失败。凭据自然到期也会阻止后续检查，不把这个保证描述成中断已经完成的持久写入。ClickHouse 执行取消需要工作进程观察到授权失效，不能宣称撤销 API 返回时所有远端 CPU 工作都已停止。

已完成结果仍是项目/环境内共享的有时限资源。读取时检查**当前读取者**的凭据及查询/原始数据权限；其他仍有权限的主体可以读取结果。撤销创建者的凭据不等同于删除项目数据，也不抹去已发布事件、分析或看板。删除与保留策略是另外的功能。

## 部署与接入资产

停止旧的功能验证进程，使用新二进制显式执行 `evia migrate`，应用到迁移目录内嵌的最新编号（全量迁移，不以历史编号为上限），再启动 API、接收工作进程和查询工作进程。迁移会改动外键并校验历史数据，生产升级需评估元数据规模、锁等待、备份和维护窗口；本轮只验证了合成本地环境与独立测试 schema。

公开业务接入材料在 [integrations](../integrations/README.md)，包含事件计划、发布和 SDK 验证三个 `activity-*` skills，以及有界 API 请求、完整发布集差异和固定白名单打包工具。它们不包含 `.agents/skills`、平台 `AGENTS.md` 或凭据，也不覆盖业务仓库自己的指令。

接入工具不是全自动发布服务。业务方的 coding agent 仍须按照 skill 逐步整理实际业务事件、比对完整发布成员及定义、保存修订与幂等键、等待真实交付就绪、激活、接入本地 SDK 包并核对实际存储事件。机器凭据由项目 owner 单独签发，工具不能自行扩大权限。
