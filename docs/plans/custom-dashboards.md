# 自定义分析、看板与公开 Agent API

状态：持续设计与实现边界，更新至 2026-11-09。已实现查询版本选择、能力/字段目录、无执行校验，以及 [保存分析的草稿、不可变发布与版本运行](../saved-analyses.md)，证据见 [本轮记录](../verification/saved-analyses-2026-11-09.md)。独立指标注册、公式、通用参数绑定、看板及机器主体仍待实现。权威请求结构是 `contracts/http/openapi.json`、`contracts/query/` 和 `contracts/reporting/`；当前保存分析直接固定事件版本，下文拟议的指标依赖与参数 AST 不能直接发送到现有接口。

看板交互包含目录侧栏、图表网格、全局时间与筛选、刷新，以及分析和元数据入口。功能以权威契约与实际实现为准；控制台基础组件迁移见 [自建组件计划](native-ui.md)。

## 1. 产品目标与当前边界

业务方先注册事件及属性、验证并发布定义，待交付就绪和显式激活后，SDK 才按允许的已发布版本发送。业务人员可在事件和字段目录中选择口径、过滤、维度及图表，保存可复用分析，组合自己的看板。业务仓库中的 coding agent 通过同一公开 API 完成相同操作，具备发现、校验、预览、版本比较、发布和执行的完整链路。

| 能力 | 当前证据 | 本设计新增范围 |
| --- | --- | --- |
| 事件及属性定义 | 事件草稿、不可变发布、就绪和激活；已发布版本及受支持顶层属性的只读分析目录已实现 | 字段语义治理、稳定字段 ID、依赖影响检查 |
| 分析执行 | `events`、`trend`、`funnel`、`journey`，持久异步任务、取消和权限复查已实现 | 可复用指标、分析版本、参数绑定、看板执行协调 |
| 查询口径 | 类型过滤、精确/显式近似聚合、原始身份、有序漏斗、显式事件版本事实选择及无执行校验已实现 | 单位、公式、聚合后过滤、跨版本显式兼容映射 |
| 保存分析、看板及 Agent | 已有会话认证的保存分析草稿、不可变版本及幂等运行；尚无看板和机器主体 | 看板目录与组件布局、独立指标注册、机器身份和审计查询 |
| 控制台客户端 | 已有真实查询工作区和保存分析编辑、发布、历史版本、运行界面 | 看板布局与统一刷新、机器 Agent 接入 |
| 数据完整性 | 覆盖状态为 `provisional`；水位为实际观察到的最晚接收时间 | 展示一致性限制，后续建立分区完整性及最终统计机制 |

`sys.*` 目前仅有契约样例，浏览器 SDK、内置事件运行时注册仍待交付。身份图、留存/分群、导出、数据生命周期也未实现。当前 HTTP 查询接收管理会话，来源写凭据不能访问查询；不能把现有路由描述成已经支持机器令牌。

## 2. 领域模型与责任

沿用单一 Go 模块、HTTP/应用策略/持久化分层。catalog 继续拥有事件与发布事实；analysis 继续拥有类型解析、规范化执行计划和任务；reporting 领域提供目录投影、校验及保存分析版本，后续扩展指标与看板。访问领域当前处理人类会话，统一机器主体仍待实现。禁止 reporting 直接修改 catalog 表或拼接另一套查询 SQL。

| 实体 | 核心内容与不变量 |
| --- | --- |
| 事件定义及发布版本 | 项目范围内稳定 `event_key`，草稿修订、不可变 `schema_version`、环境发布资格；由现有 catalog 管理 |
| 分析字段目录条目 | 发布事件中的字段投影，带类型、单位、允许用途和敏感级别；不是另一份独立字段定义真源 |
| 指标 `metric` | 稳定字符串 ID、名称、草稿修订、不可变版本；固定事件集合、统计主体、聚合、单位、过滤和精度 |
| 保存分析 `saved_analysis` | 稳定 ID 及不可变版本；分析类型、指标版本、维度、参数定义、时间语义及受限呈现配置 |
| 看板目录 `dashboard_folder` | 项目/环境范围内父目录、标题、排序、修订；禁止环和跨范围父节点，默认继承项目权限 |
| 看板 `dashboard` | 稳定 ID、目录、草稿修订、发布版本指针、生命周期；重命名/移动也参与并发控制 |
| 看板版本 `dashboard_version` | 不可变内容和依赖清单，包含组件、布局、默认参数、筛选绑定及内容哈希 |
| 组件 `widget` | 看板内稳定字符串 ID，引用指定分析版本及呈现配置；不携带查询结果 |
| 看板运行 `dashboard_run` | 操作者、确定的看板版本、绝对时间范围、参数、子查询和逐组件状态；独立到期策略 |

所有实体及读取、缓存、任务、唯一键均受授权项目和环境约束。ID 使用不透明字符串；版本和修订是有界安全整数。第一阶段不创建公开匿名链接或跨项目引用。需要团队共享时复用项目成员权限；未来对象 ACL 只能收紧有效权限，不能绕过项目边界。

### 2.1 草稿、发布与激活是不同生命周期

事件草稿修改通过现有 `If-Match` 比较修订；构建事件 release 产生不可变定义。就绪证明和激活决定来源现在可以发送什么版本，发布本身不授予采集资格。SDK 自动读取配置、接收白名单和禁用后的失效时限继续遵循 [发布说明](../releases.md)。没有注册的事件或未允许的属性不能依靠 SDK 首次发送自动创建目录。

指标、保存分析和看板均采用“可修改草稿 → 校验与预览 → 创建不可变版本”。看板发布只原子切换自己的发布指针，不激活事件 release，也不替用户开启来源。看板使用已发布依赖，运行时仍复查当前权限和数据保留边界。退回旧版界面通过创建引用旧内容的新看板版本完成，历史不改写。

草稿保存须 `If-Match`；不可变版本创建和发布须幂等键及预期草稿修订/当前发布版本。版本提交在一个 PostgreSQL 事务中校验依赖、写内容、改指针和记审计。发布前返回语义 diff：指标口径、事件版本、字段类型、过滤条件、权限影响和布局变更分开列出。引用新的指标/分析版本必须显式接受 diff；保存了新指标不会悄悄改变所有旧看板。

## 3. 已发布事件与字段目录

第一步从现有发布 manifest、事件 Schema 和字段元数据生成只读分析目录，不创建与 Schema 脱节的“全局属性注册接口”。当前分析属性引用是 `{kind: "property", event_key, schema_version, key}`，仅支持受控顶层属性键；系统字段引用另有固定白名单。服务端从指定环境的不可变发布版本解析类型，客户端不能提交 `resolved_type`。

已实现目录返回 `catalog_revision`、环境、不可变版本及定义哈希、`published`/`active`/`ingestion_ready`、受支持顶层属性的类型、必填及空值/缺失语义、原始字段元数据和允许操作。`ingestion_ready` 仅投影当前激活 release 的有效证明；历史版本仍可查询，不要求当前激活或接收就绪。分页游标绑定操作者、项目和环境，不能当跨页快照。当前没有 `queryable` 布尔值，也没有单位/敏感级别治理；详见 [实际类型子集与状态定义](../reporting-discovery.md)。未来再扩展稳定字段身份和治理能力。

新增稳定 `field_id` 时，由 catalog 在发布事务中分配并保存版本映射；不能用显示名称当身份，也不能假装当前已有此 ID。分析编译时将 ID 解析成明确的事件、版本和路径。嵌套路径、对象展开、用户属性等另增契约和存储支持后开放；当前 `key` 不解释为任意 JSONPath。

| 变化 | 处理规则 |
| --- | --- |
| 改显示名或说明 | 创建新元数据版本；历史分析仍可解释原口径，界面可显示当前别名 |
| 添加可选字段 | 新事件版本；旧数据缺失保持缺失，不填默认业务值 |
| 类型、单位、事件含义变化或收紧必填 | 不兼容变更；新版本、发布 diff、受影响分析列表，禁止隐式跨版本聚合 |
| 属性更名 | 新字段身份及显式迁移映射；没有审核映射时不能合并两个字段 |
| 删除/弃用字段 | 阻止新引用并保留历史版本及依赖说明；已存数据按保留政策处理 |

跨多个事件共享的“板块”“设备”等逻辑维度，是有版本的字段绑定集合，每个绑定保留事件版本和真实类型。只有类型、单位及业务含义兼容时才可合并。维度表、用户属性、虚拟事件/属性、会话口径和统一指标目录是后续领域能力；其导航入口依据服务端能力开放，不能用静态空壳表示已交付。

## 4. 指标、公式与保存分析

### 4.1 统一统计语义

- **事件次数**：选定事件集合后 `count`。标准 PV 按当前语义绑定 `sys.page_view`；运行时注册完成前不能宣称自动 PV。自定义 `forum_page_view` 可定义“论坛页面访问次数”，须明确页面触发规则、来源及事件版本；产品若展示业务 PV，必须同时显示此事件口径，不能把任意点击次数命名 PV。
- **UV**：`unique` 明确选择 `uid` 或 `anonymous`。UID 缺失和空值不计；匿名身份是原始匿名标识，不能宣称已去重为人。不同分组可能包含同一个人，分组 UV 之和不等于总体 UV；不能据此自动生成互斥占比或“其他人数”。`resolved_person` 及身份修订只有身份图真实实现后开放。
- **时间**：查询是 `[from,to)`，固定 UTC 时间戳和 IANA 分桶时区。自然日、滚动 24 小时和昨日是不同预设，按所选时区解析，测试夏令时。整段 UV 必须整段计算，不能相加每日 UV；平均数、分位数、比例也不能简单累加桶值。
- **空值**：无观察值的 count/unique 为 0，数值聚合无有效观察为 null；缺失、显式 null、false、0 保持区别。没有有效覆盖证明的缺桶不能补成确定的 0。图表缺口、无数据和执行失败分别表达。
- **精度与覆盖**：默认精确；近似 UV/p95 必须显式选择并传递结果精度。始终显示生成时间、采样率、覆盖状态及已知缺口。当前 `data_watermark` 是查询实际观察到的最晚 `received_at`，不能表示“此刻之前均已到齐”。
- **版本与去重**：使用既有来源范围内的事件去重视图，不以图表本地去重替代。`event_versions` 已在契约、发布资格校验和 ClickHouse 事实谓词实现精确配对，每事件暂限一个版本；漏斗通过步骤固定版本。`event_keys` 仍跨版本，未选择事件仍为 `all_events`；属性依赖或校验哈希不代表事实已固定。跨版本兼容映射仍待实现，不能仅在保存配置 JSON 中承诺固定版本。

可复用原子指标包含事件选择、固定行级过滤、聚合、字段/主体、精度、单位和允许参数。显示格式不是单位；毫秒与秒必须显式换算，金额必须标明币种。次数、人数、时长、货币、无量纲比例参与类型检查；相加/比较要求单位兼容。UV 标为不可加，不能将预聚合的 UV 数字再次求和。

下面是**拟新增的指标定义片段**，不是现有 `QueryRequest`；编译器须先解析版本选择，再生成现有或正式扩展后的类型查询：

```json
{
  "name": "论坛登录访客",
  "event_selection": [
    { "event_key": "forum_page_view", "schema_versions": [1] }
  ],
  "aggregation": { "op": "unique", "subject": "uid", "accuracy": "exact" },
  "unit": { "kind": "person", "identity": "raw_uid" },
  "row_filter": null,
  "allowed_parameters": ["section", "time_range", "timezone", "interval"]
}
```

### 4.2 筛选与公式

行级 `row_filter` 在聚合前执行，限制事件事实；`aggregate_filter` 在聚合完成后限制指标结果或分组。界面分别显示“事件筛选”和“指标结果筛选”，例如 `section_id = news` 与“访问次数 ≥ 100”不能交换执行顺序。现有查询只有行级过滤，聚合后过滤必须实现类型契约、编译和预算检查后再开放。

公式使用受限的有类型 AST，允许已发布指标引用、常量、加减乘除及有界条件选择。禁止 SQL、任意 JavaScript、外部 URL、用户函数和图表回调。引用依赖构成无环图，限制深度、节点数和指标展开总量；首版建议深度 8、最多 100 节点、展开后最多 10 个原子指标，实际限额由能力响应给出。

例如浏览到发帖率为 `divide(metric(posting_users@2), metric(visitors@3))`，两者主体、时区、时间窗及过滤维度必须可对齐。除零返回 null 并附 `division_by_zero` 状态；缺失输入传播 null，只有显式 `coalesce` 才能替换，并在校验时说明统计影响。禁止自动把失败查询当零。溢出、非有限数字和不兼容单位返回字段错误。比例应声明定义和分母，独立事件计数之比不保证不超过 100%，不能伪装成漏斗转化率。真正的有序漏斗按同一主体的逐步到达集合计数，后一步集合嵌套于前一步；分母非零时步骤/总体转化率应在 0–100%，未到达第一步则返回无定义的转化率，不能强行显示 0%。

### 4.3 保存分析与分析类型

保存分析固定指标版本、维度、粒度、参数定义和可用图表。参数绑定只替换有类型的值，不能替换 AST 运算符、表名或任意字段。服务端规范化 AST、解析发布类型、校验权限和预算后，再用参数绑定的既有 analysis 引擎执行；UI 与 Agent 共享相同校验。保存分析是可复用配置，查询任务是一次执行，两者 ID 和权限不得混用。

| 分析 | 首次交付条件与展示 |
| --- | --- |
| 事件趋势/指标 | 首先复用已实现 trend；数值卡、表格、多序列折线、面积、柱状和维度条形图 |
| 有序漏斗 | 复用已有 ordered 模式及窗口/同实体语义；步骤条形和转化表，显示主体和窗口 |
| 原始行为链/事件详情 | 复用已有受限单身份查询与事件明细；独立原始数据权限，不能自动向所有看板读者开放 |
| 构成/分布 | 构成来自明确分组和分母，分布需有类型分桶定义；饼图限制类别并提供表格，直方图不能用任意柱图冒充 |
| 留存/群组 | 先定义初始事件、回访事件、主体、周期、时区、观察成熟度，再实现 cohort/retention 计划和矩阵 |
| 聚合路径 | 先定义节点、会话边界、跳出、循环压缩和路径预算；原始 journey 不等于聚合路径/Sankey |
| 归因/生命周期 | 先定义触点及窗口、模型版本、活跃/流失规则；提供可解释结果和相应引擎 |
| 热图/回放 | 需要页面定位/录制协议、同意与脱敏、专用存储和播放授权，不能从普通事件表推断已支持 |
| 用户详情、用户群与元数据扩展 | 身份图/用户属性/群组版本、保留及敏感权限到位后提供相应分析与目录 |

服务端能力发现返回实际支持的分析、聚合、字段操作、图表映射和预算。客户端不根据菜单文字猜支持情况；未实现功能可在规划说明中展示，不能提供会返回假数据的可操作分析页。

## 5. 看板编辑与运行界面

项目/环境选择位于工作区范围；左侧显示可搜索目录和看板，支持新建、重命名、移动、复制与归档。目录深度建议上限 5；归档目录须先处理非空子项，不做隐式递归删除。复制创建新 ID，保留明确的版本依赖，跨环境复制必须重新绑定并校验，不能沿用原环境权限或发布资格。

主区由标题和发布状态、全局时间/时区/刷新、可读筛选条、组件网格组成。每张图显示标题、单位、口径入口和独立状态；状态包含排队、执行、无数据、部分覆盖、失败、取消及过期。筛选改变后保留旧结果时，必须清楚标注旧参数及刷新中状态，不能把它当新结果。一个组件失败不清空成功组件，也不把整次运行显示为完全成功。

编辑从保存分析选择组件，也可先创建分析再加入。支持组件标题、图例、轴、排序、单位格式、比较时间、维度数量和布局；允许有限、版本化的语义配置，不持久化底层图表库的任意 option 对象。Markdown 文本卡仅允许净化后的有限标记，禁止脚本、iframe 和任意 HTML。

`packages/design-system` 提供自有 React/HTML 筛选、日期、选择器、布局、键盘和状态组件；图表用成熟渲染库封装。ECharts 是折线、柱状、漏斗、热力及后续路径图的候选，需要评估无障碍、许可证、维护和体积，采用限定模块导入及按路由/图种延迟加载。本次只做方案，不新增包或锁文件。所有图表提供可读摘要和表格，颜色之外用线型/符号区分，减少动画偏好生效。

布局使用 12 列语义网格，坐标及尺寸为整数，范围校验、最小宽高和碰撞处理在服务端及 UI 一致。窄屏按显式阅读顺序单列排列；不能仅按视觉坐标决定 DOM 顺序。拖动和缩放都有键盘替代操作及移动/尺寸按钮，调整后宣告位置，取消恢复原布局。筛选条件有完整标签、类型、逻辑关系和删除按钮；长条件不被截断为不可理解缩写。

### 5.1 全局筛选如何作用于组件

每个全局参数有稳定 `parameter_id`、类型、允许值/运算和默认值。每个组件显式将参数绑定到保存分析的已声明参数；分析再将参数映射到已发布字段。相同显示名称不能自动绑定不同事件属性。多事件分析必须为每个适用事件给出映射；缺少映射时发布失败，或作者明确标记不适用并在界面显示原因。

组合顺序是：指标固定过滤 AND 保存分析固定过滤 AND 全局参数绑定 AND 组件局部过滤；不能由全局参数删除固定约束。时间默认继承全局，局部覆盖须有可见标签和发布时声明。比较期使用相同主体、粒度、过滤和单位，并明确偏移方法；夏令时不能仅减固定秒数得到“上周同日”。

## 6. 查询协调、预算与一致性

看板运行由服务端协调，浏览器只提交看板版本和参数，不为每个组件自行无限创建任务。协调器展开版本依赖，规范化并合并完全等价的查询，再提交现有持久任务；组件仍保留自己的结果映射。规范化不能交换有序漏斗步骤，也不能通过布尔简化改变缺失/null 语义。所有字段和常量都经过类型检查与参数绑定，禁止用户提供 SQL、表名、函数体或图表执行代码。

每次刷新先将相对时间一次性解析为绝对范围，冻结时区、参数、目录和分析/指标版本，产生 `run_id`。既有任务当前没有跨查询快照屏障：同次刷新各组件可能观察到不同的最新接收事件，必须分别返回生成时间、水位和覆盖。未来若实现 `snapshot_cutoff`，需对所有查询施加相同的已接收事实界限，并证明重放、去重和迟到语义；现在不能用相同 `run_id` 宣称原子快照或完整数据。

当前每项目最多 4 个执行和 32 个等待任务，趋势最多 31 天，其余查询最多 7 天，最多 3 个分组、10 个指标和 500 行，详见 [查询说明](../analysis.md)。看板、预览、Agent 和直接查询必须共享这些项目预算，不能因套一层看板而增加四倍并发。后续放宽限额必须有真实联合负载证据。

拟新增看板初始保护：最多 24 个组件、展开后最多 32 个不同查询、每看板最多 2 个执行中的子任务，仍受项目 4 个执行上限约束；不一次占满全部 32 个等待位置，预留交互配额并按主体公平调度。自动刷新最短建议 60 秒，运行未结束不叠加，隐藏标签页暂停并加入抖动。具体默认值写入服务端配置及能力接口，不能硬编码为容量承诺。

后续须在查询前估算事件/时间/分组基数、桶数×序列数、公式展开、返回体积及执行成本；当前校验仅实施既有静态预算，没有实际扫描成本估算。高基数字段需明确上限；超预算报错并建议缩小条件。Top N/其他类别如开放，必须定义排行依据、全集分母和 `other` 算法，不能由浏览器截取前 20 行后把比例当完整。当前底层超限会失败，不应假称已支持自动 Top N。首版多序列图只能使用当前 500 行内完整返回的数据；例如 31 天×20 个分组超过此界限，预检应拒绝并提示减少分组/范围或增大已支持的粒度，不能静默截断、降采样或把多个窗口结果拼成有偏 UV。完整长周期、多序列与可控抽样需先扩展查询契约、结果预算和精度标记，取得真实负载证据后再开放。

运行状态单独定义为 queued/running/succeeded/partial/failed/canceled/expired；其中 partial 是看板聚合状态，不向当前 `QueryJob.state` 塞入未定义枚举。每组件返回 `query_id`、状态、错误码、是否可重试、结果位置与元数据。轮询遵循服务端间隔和指数退避；取消运行撤销其订阅，只有无其他授权订阅者时才取消共用子任务。权限失效立即停止结果发布，取消远程执行沿用既有租约和 ClickHouse 终止链路。

### 6.1 缓存与失效

当前没有查询缓存。本设计缓存实施在持久任务和授权之后，Redis 只保存有界短期结果/协调数据。缓存键至少包含项目、环境、有效授权范围及权限修订、规范化查询哈希、看板/分析/指标版本、已解析目录依赖、绝对时间、时区、精度、采样、身份修订以及数据与生命周期世代。

数据水位不能在执行前凭空得出。先以可信数据世代或已知水位选择候选项；复用时验证缓存记录对应的水位/新鲜度，无法证明时按 TTL 标为旧快照或重新执行。未来完整性水位可支持封闭时间窗的更长期缓存；当前 `provisional` 查询只允许短 TTL，界面仍显示原生成时间。用户手动刷新请求重新验证/执行，不能只改变“最后刷新”标签。

每次命中前重新授权；撤销主体、令牌、成员权限后不得使用旧缓存继续读取。敏感字段许可属于缓存授权范围。保留期推进、删除、归档恢复、回补和身份修订触发项目/环境世代递增及关联结果失效；删除屏障需要同时覆盖持久任务结果、导出和缓存，不能只清 Redis。尚未具备可靠失效链时不启用跨请求结果缓存。

## 7. 同一 API 面向 UI 与 coding agent

复用 `/api/v1` 管理/查询命名空间，公开表示“受支持的集成契约”，不表示匿名可访问。UI 和 Agent 调用同一资源与应用策略；人类会话保持 CSRF，拟新增机器 bearer 通过独立认证适配器解析成统一主体。不得通过共享 Cookie、模拟登录或让业务 agent 修改平台数据库获得能力。

创建及发布拟新增资源使用 `Idempotency-Key`；绑定主体、项目、环境、操作和规范化请求内容。重试同键同内容返回原结果，同键不同内容为 409。所有草稿写入要求单个带双引号的 `If-Match` 修订，沿用现有事件和来源接口语义：缺少或格式非法为 400 `REVISION_REQUIRED`，修订不符为 409，并返回该资源的稳定冲突错误码；依赖/发布冲突同为 409。后续若统一调整条件请求状态码，须单独演进全局契约和客户端，不能由看板模块引入另一套规则。列表使用 `{items,next_cursor}`，响应资源不额外包 `data`。

校验错误保留稳定大写 `code`、`request_id` 和字段路径；例如 `FIELD_NOT_PUBLISHED`、`UNIT_MISMATCH`、`PARAMETER_BINDING_MISSING`、`QUERY_COST_EXCEEDED`、`DEPENDENCY_VERSION_CONFLICT`。异步预算/执行失败通过任务状态返回，不能用 HTTP 200 的“成功图表”掩盖失败。

### 7.1 机器主体及权限

机器主体是项目范围内独立 actor，可绑定允许的环境、角色、用途、所有者和到期时间。短期令牌只返回一次，持久化不可逆摘要；不写入浏览器本地存储、看板 JSON、生成示例或日志。支持轮换、立即撤销及有界认证缓存；管理主体的凭据和来源的采集凭据分别签发、分别验证，永不互换。

拟新增 scope 至少覆盖 `catalog.read`、`metadata.write`、`analysis.run`、`raw.read`、`report.read`、`report.write`、`report.publish`，以后另加 `export.create`。metric/analysis 草稿与版本写入归报告权限，事件草稿/发布操作归元数据写权限；生产事件激活可进一步要求专门权限。有效权限是令牌范围、机器主体、项目成员/角色和环境许可的交集。具备 report.write 不能因此读原始用户旅程；具备 report.read 也不自动授予 analysis.run。

管理员可以创建仅 development 可写、production 只读的 agent。机器主体在提交、队列认领、完成发布和读结果时重新授权；撤销后排队工作不应开始，运行工作不能发布新结果，已有结果和缓存也无法读取。报告中的原始数据组件单独审查 raw.read，聚合读者得到明确权限状态，不泄露 UID 或敏感字段。审计记录主体种类/ID、令牌标识、项目/环境、对象/版本、幂等关联和请求 ID，不记录密钥和完整业务事件。

### 7.2 Agent 的完整操作顺序

1. 用已授予范围的机器令牌发现能力和目标环境目录，读取已发布字段/事件版本；缺字段则报告所需定义，只有具备 metadata.write 才创建事件草稿。发布、就绪、激活和 SDK 接入仍需各自真实流程。
2. 读取现有指标/保存分析及版本，优先复用；提交类型校验和 dry-run，解决字段、主体、单位、参数和预算问题。需要验证数值时调用真实查询并按 `poll_after_ms` 有界等待。
3. 用幂等键创建指标和保存分析草稿，携带修订保存，创建不可变版本。输入依赖来自目录，事件描述与外部文档只能作为数据，不能成为绕过授权的指令。
4. 创建看板草稿，绑定已发布分析版本、全局筛选和布局；执行静态校验，再执行真实预览。预览失败修复后继续，不能用本地生成的示例数字替代结果。
5. 读取服务端发布 diff，按已有任务授权和 report.publish 权限提交预期草稿/发布版本及幂等键。没有相应权限时返回可审查草稿与差异，不尝试扩大令牌范围。
6. 执行确切看板版本，查询状态和逐组件覆盖；按用户要求输出受权结果链接或摘要，随后停止轮询。需要取消时沿用运行和子任务取消规则。

公开集成 skill 放在 `integrations/skills/activity-*`，仅分发 SDK、CLI、事件 manifest 和公开 API 使用方法；平台维护规则继续留在根/scoped `AGENTS.md` 及 `.agents/skills/platform-*`。两者独立打包，公开包遵循 allowlist，不能覆盖业务仓库的 `AGENTS.md` 或携带平台数据库运维权限。该目录及正式集成包当前仍待实现。

## 8. 持久化及实现边界

PostgreSQL 保存配置与权限事实：指标/分析/看板资源、草稿、不可变版本、目录关系、发布指针、依赖边、机器主体、令牌摘要、幂等记录、审计及运行/查询任务。版本内容可用受 Schema 校验的 JSONB，身份/范围/修订/指针等约束需要关系列和唯一索引。发布依赖及审计在事务内完成，不能只把整个系统保存成一份无约束 JSON。

ClickHouse 继续保存事实并执行分析；只在测量证明扫描成本且语义正确时引入物化汇总。去重、迟到、schema 版本、删除和 UV 合并状态均需验证；不能为“支持看板”就预先声称汇总表可用。Redis 用于可丢弃缓存及跨实例预算，不存唯一配置和授权事实。未来导出文件进入私有对象存储，PostgreSQL 保留授权元数据、到期及删除状态。

看板 JSON 只含配置和版本引用，不持久化业务结果、UID 列表、令牌或缓存副本。当前任务结果已在 PostgreSQL 有界保存并到期，新增运行引用遵循相同结果授权和更短者到期原则；配置历史可以长期保留，不能因此延长用户数据保留期。备份恢复后须重建删除屏障和失效世代，再允许读取历史任务/导出。

## 9. 交付阶段与可检查结果

完整方向保留，执行继续服务端优先。每阶段先契约、领域及持久化，再 HTTP 与真实依赖证据，最后连接控制台；不能先做一套无后端语义的看板演示代替交付。

| 阶段 | 后端结果 | 对应控制台及集成结果 |

## 10. 验收证据

- **目录与类型**：草稿字段不能作为已发布字段使用；跨项目/环境字段、伪造类型、跨版本不兼容合并、单位冲突和嵌套路径注入均拒绝；事件发布/激活的既有链路保持真实有效。
- **统计**：合成论坛数据同时验证次数、UID/匿名 UV、缺失/null/false/0、空集、精确/近似精度、时区及夏令时、每日 UV 不可加、公式除零/空值/单位与聚合前后过滤顺序；覆盖和水位保持真实含义。
- **版本及事务**：两人/两个 agent 并发编辑产生显式冲突；幂等重试不重复创建版本，异内容同键拒绝；依赖被更新/弃用时旧版本稳定且新发布重新校验；审计失败回滚，发布后修改被数据库策略拒绝。
- **授权及撤销**：真实 PostgreSQL 测试项目/环境隔离、人/机器权限交集、raw.read 边界；提交前、排队中、执行中及命中缓存前撤销令牌均不能泄露结果。来源写凭据不能调用报告 API，浏览器会话继续校验 Origin/CSRF。
- **预算及取消**：多看板、预览、直接查询和 agent 并行遵守同一项目预算；高基数/超大布局/公式展开拒绝；真实 ClickHouse 证明运行取消、失效租约阻止发布、单组件失败和整体 partial、结果到期/保留删除后的缓存失效。
- **浏览器与 Agent 同一闭环**：连接真实 API、PostgreSQL 和 ClickHouse，从已发布论坛事件创建分析、看板草稿、筛选预览、diff、发布及刷新；独立 API 客户端读取相同版本与数值，再编辑触发 UI 修订冲突。验证空数据、失败重试、401/403、取消、旧结果标签和未保存输入保护。
- **交互及性能**：桌面/移动截图人工检查，键盘移动/缩放、焦点恢复、可读筛选、表格替代、长标题及布局边界通过；按同一设备/网络记录入口与延迟图表体积、运行查询数、首图时间及多图交互延迟。结果附硬件、数据量、并发和故障条件，不能仅凭构建成功宣称性能提升或生产容量。

实现时同步权威契约、生成客户端、合成样例、迁移、权限与错误测试，再把实际证据和剩余边界写入 `PROGRESS.md`。本文本身只提供可实施设计，不构成新能力已验收的证明。
